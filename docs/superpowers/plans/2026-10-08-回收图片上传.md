# 回收图片上传实施计划（需求 V1.1 第四优先级）

日期：2026-10-08 ｜ 分支：feature/recycle-mvp ｜ 状态：进行中

## 目标

回收下单支持用户上传机器照片（正面 front / 背面 back / 屏幕 screen / 损坏 damage，合计 ≤9 张），
详情与管理端可见。不改回收订单核心流程与状态机。

## 复用与新做

- **上传签名**：`GET /api/wx/cos/upload-sign?dir=recycle` 已存在（P1 目录白名单，recycle 为默认值）✅ 零改动复用。
- **存储**：`recycle_order` 增加 `images_json`（存量库走 patch-recycle-images.sql），格式 `[{type,url}]`
  （url 实为 COS key，与维修/评价图片同口径；mock 模式存临时路径）。
- **校验**：选填；≤9 张；type 白名单 front/back/screen/damage；url 白名单字符（防目录穿越）。
- **小程序**：下单页 4 组照片位（每组可多张、总计 ≤9、删除/预览、提交时逐张上传并显示"正在上传 x/y"进度）；
  详情页机器照片栅格（类型标签 + 预览）。COS 直传为 wx.request PUT（COS XML API 只收裸 body，
  wx.uploadFile 的 multipart 不适用，进度以逐张计数文案呈现）。
- **管理端**：回收单详情抽屉新增「用户上传图片」区（类型标签 + 展示；COS key 非 http 时以文本呈现，控制台可查）。

## 非目标

- 不做 COS GET 签名回显（keys 管理端文本呈现；真实图片查看走 COS 控制台/后续统一回显方案）。
- 不改回收状态机、质检、打款流程；质检照片（inspection）不动。

## 验收 / 风险

- RecycleImageFlowTest（独立 H2 库 mem:rimg，含 schema-quote 复核估价链）：正常保存与回显、数量限制、
  类型/路径非法拒绝、越权查看 403、租户隔离 404/本租户正常。
- 不传图片的既有下单路径零影响（P3OrderFlowTest 回归）。
