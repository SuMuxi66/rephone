# 评价系统实施计划（需求 V1.1 第一优先级）

日期：2026-10-08 ｜ 分支：feature/recycle-mvp ｜ 状态：进行中

## 目标

用户在维修/回收/出售订单**完成后**可对订单评价（1-5 星 + 文字 + 图片），管理端可查看全部评价。
对应需求文档第 8 节「用户评价」与 V1.1 开发任务第一优先级。

## 范围

- 新表 `comment`（幂等 schema，MySQL 8 / H2 通用），带 `tenant_id`，`order_type + order_no` 唯一防重复评价。
- 用户端接口：创建评价、按单查评价（挂在 `/api/wx/comment`，遵循仓库现有 `/api/wx/**` JWT 规范；
  需求原文的 `POST /api/comment` 按现有接口规范落位，路径映射在交付说明中注明）。
- 管理端接口：`GET /api/admin/comment/list`（分页 + 类型/单号/星级筛选），登记新权限点 `comment:manage`。
- 管理端页面：评价管理（Comment.vue + 路由 + 菜单 + 权限点清单）。
- 小程序：评价服务层 + 评价页（星级/文字/COS 图片直传）+ 三类订单详情页接线
  （已完成态显示【立即评价】，已评价显示评价内容）。
- COS 签名支持可选 `dir` 参数（白名单 recycle/repair/comment，默认 recycle 保持旧行为）。

## 非目标

- 不做评价的商家回复、评价删除（合规删除后续按需加）。
- 不动出售商品详情页的评价展示（仅订单维度）。
- 不做维修报价/支付/回收图片上传（第二至四优先级，另立计划）。
- 不重构现有支付、订单代码。

## 关键决策

- `order_type` 复用 `order_status_log` 的既有取值：10 回收 / 20 出售 / 30 维修。
- 订单引用存 `order_no`（业务订单号，与全仓接口口径一致），不存自增 id。
- 可评价条件：订单归属当前用户 + 状态已完成（回收 60 / 出售 40 / 维修 50）。
- 表名列 `create_time/update_time`（与全库一致；需求原文 created/updated_time 以仓库约定为准）。
- 防重复：唯一键 `uk_comment_order(order_type, order_no)` + 服务层前置校验给友好文案。

## 任务 / 提交拆分

1. `docs(plans)`：本计划。
2. `feat(server)`：schema + 实体/Mapper/Service + Wx/Admin 控制器 + 权限点 + COS dir 参数
   + H2 集成测试 CommentFlowTest（`mvnw test` 全绿后提交）。
3. `feat(admin)`：Comment.vue + api + 路由 + 菜单 + permissions 清单（@vue/compiler-sfc 静态校验）。
4. `feat(miniprogram)`：services/comment.js + pages/comment/create 四件套
   + 三类订单详情页接线 + app.json 注册（babel/JSON/wxml 静态校验）。

## 验收标准

- H2 集成测试覆盖：三类订单创建评价、重复评价被拒、未完成/非本人订单被拒、参数校验、
  管理端分页筛选、未登录 401。
- 管理端可按类型/单号/星级筛选评价列表。
- 小程序三类订单详情页：已完成显示【立即评价】→ 评价页提交 → 返回详情可见评价内容。
- 既有接口行为零变更（COS 签名默认目录不变）。

## 风险

- `comment` 为 MySQL/H2 非保留关键字，建表用反引号 + H2 测试实跑验证。
- `app.json` 存在并行会话未提交改动（模板死页面登记移除），本任务必须同文件注册新页面；
  提交时在答复中显式声明该文件携带并行改动。
- Mimosa 钩子对小程序 JS 模板字面量的已知误报：评价页代码避免 `#${x}` 形态。
