# 维修真实支付链路实施计划（需求 V1.1 第三优先级）

日期：2026-10-08 ｜ 分支：feature/recycle-mvp ｜ 状态：进行中

## 支付架构检查结论（需求第一部分）

| 检查项 | 现状 | 结论 |
|---|---|---|
| 微信支付配置 | `WxPayProperties`（rephone.wxpay.*，WXPAY_MCH_ID/MCH_KEY/CERT_PATH/MOCK 已绑定环境变量）+ `WxProperties.appid` | ✅ 直接复用 |
| JSAPI 下单逻辑 | 无（全仓无 unifiedorder/prepay 代码；出售支付为 mock 内联） | ➕ 新建 WxPayClient |
| 回调 Controller | 仅快递100 回调（`/api/callback/kuaidi100` 匿名回调先例） | ➕ 新建 `/api/callback/wxpay` |
| 签名验证 | V2 MD5 签名先例（WxPayoutService.sign，协议强制） | ✅ 按同模式实现 |
| 支付订单表 | 无（出售侧 pay_no 挂订单） | ➕ 新建 payment_order |

**技术路线**：微信支付 **V2 JSAPI**（与仓库既有 V2 凭据体系/MD5 签名一致，不引入 V3 证书体系）；
mock 模式闭环（沿用仓库第三方接入惯例），**回调验签/金额/商户号校验全真实现**（测试可覆盖）。

## 关键设计

- **payment_order 表**（新）：tenant_id/order_no/order_type(20出售 30维修)/pay_no/amount_fen(分)/status(0待支付 1已支付 2已关闭)/transaction_id/create_time/pay_time，pay_no 唯一。金额一律分。
- **统一入口 PaymentService 扩展**：`start(orderType, orderNo, amountFen, tenantId, openid)` 建/复用待支付单并返回 JSAPI 参数（mock 模式返回 {payNo, mock:true}）；`markPaySuccess(payNo, transactionId)` 幂等入账。订单状态分派在回调层（避免 service 循环依赖）。
- **支付流程**：pay（PUT，既有路径）→ 38 校验 + 报价金额 → start → 真实模式返回 wx.requestPayment 参数（等待微信回调）；mock 模式模拟回调闭环（同一 handlePaid 路径）。回调：验签 → mch_id/appid/total_fee 比对支付单 → 幂等入账 → REPAIR 分派 `RepairOrderService.markPaid`（CAS 38→30 + pay_no + 状态日志，operator=系统）。
- **幂等**：重复通知→重复回调直接返回 success 不重复推进；同订单已有待支付单则复用 payNo。

## 非目标

- 不迁移出售支付到 payment_order/回调（保持 mock 内联，接口零变化；回调层预留 SALE 分派点）。
- 不接 V3、不做退款回调、不对账任务。

## 任务 / 提交拆分

1. `docs(plans)` 本计划；2. `feat(server)` schema+配置+实体+客户端+服务+回调+测试；3. `feat(miniprogram)` 支付调起与页面接线。管理端无变化（报价操作不受影响）。

## 验收标准 / 风险

- RepairPaymentFlowTest：正常支付、重复支付、金额篡改、回调重复通知、签名错误、越权、支付后推进。
- 真实联调需商户号/API 密钥/notify-url 环境变量（.env.example 同步），未配时 mock 闭环不阻塞。
- 风险：门禁拦截模式（WxPayClient 含协议强制 MD5，预期进隔离名单，走 hash-object 入库姿势）。
