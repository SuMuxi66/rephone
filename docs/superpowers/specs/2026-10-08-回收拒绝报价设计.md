# 回收「拒绝最终价」设计（V1.3 仅设计，不实现）

日期：2026-10-08 ｜ 状态：待排期 ｜ 关联：RecycleOrderService / WxRecycleOrderController / 审计 M1

## 背景

审计 M1：回收单在 40 待确认态时，用户只能「确认打款」（40→50）或整单取消（40→80），
没有「对质检最终价不满意 → 退回重新质检」的中间出路。机器此时在平台侧，取消意味着
逆向寄回流程，成本高。

## 设计

### API

- 新增 `PUT /api/wx/recycle/order/{orderNo}/reject-price`（用户端，requireOwned）。

### 行为

- 仅 `40 待确认` 可拒绝；CAS 40 → 30 质检中，`order_status_log` 记录
  （operator_type=10，备注「用户拒绝最终价，退回重新质检」），订阅消息照发。
- 管理端在 30 态重新提交质检（既有 `POST /api/admin/recycle/order/{orderNo}/inspection`）：
  inspection 表本就支持多条记录，`order.finalFen` 以最新一次为准，再次进入 40 待确认。
- 用户取消整单仍走既有 40 → 80（不变）。

### 状态机变更

```
WAIT_CONFIRM 增加出边：→ STATUS_INSPECTING（用户拒绝触发，仅此一处）
```

### 边界与防滥用

- 拒绝次数限制：order 增加 `reject_count`（TINYINT 默认 0）或以 order_status_log 中
  「40→30 且 operator_type=10」计数；超过 2 次后拒绝改为「转人工」（提示联系客服），
  防止无限拉扯。推荐后者（不加列）。
- 拒绝不修改 final_fen；新最终价以管理端再次质检提交为准。
- 金额护栏沿用现状：新 finalFen ≤ 估价 ×2（40029）。

### 测试要点

拒绝→40→30→重新质检→40 二轮；拒绝后取消 40→80；非 40 态拒绝被拒；次数上限转人工；
订阅消息字段（reject 文案）。

### 影响面

RecycleOrderService（一个方法 + TRANSITIONS 一条边）、WxRecycleOrderController（一个端点）、
小程序详情页 40 态增加「拒绝并退回」次按钮；无表结构变更（推荐不加列的计数方案）。
