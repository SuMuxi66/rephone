RePhone 首页改版设计稿 v2

2026-09-30 ｜ 分支 feature/recycle-mvp ｜ 状态：待你确认后落地

一、为什么改

现在的首页是 2026-09-29「维修主导」改版的产物，当时平台只有维修 + 回收两个业务， 首页结构是：维修主卡 → 三保障 → 热门维修 chips → 回收次卡 → 热门机型。

但之后新增了 「购买」（严选二手机） 业务并占据了第 2 个 tab，首页却完全没有它的位置； 同时首页缺少搜索入口，也无法承载「质检」这个平台最核心的信任卖点。

二、信息架构（自上而下）

顺序模块作用状态
1定位 + 全局搜索降低寻找成本，搜索覆盖机型/故障/二手机新增
2维修主卡（浮起大卡）平台定位锚点，最强 CTA强化
3回收 / 购买 双卡两条业务并列，各有价格钩子与 CTA新增购买
4哪里坏了（快捷故障）维修最高频入口，从横滑改宫格改造
5严选二手机 横滑购买业务转化位，卡片带成色 + 质检标新增
6热门机型回收 横滑保留原品牌预选估价链路保留
7服务保障四宫格把三个保障和「官方质检」并在底部统一背书调整

三、关键设计决策

  • 维修仍是唯一主卡。三业务不是平均用力——维修占满一整行大卡并浮在头部之上，回收与购买各占半宽。 这样维持「维修主导」的定位，同时给新业务合理曝光。
  • 头部渐变延伸到状态栏。品牌色大色块建立记忆点，搜索框压在渐变上形成层次，维修主卡向上负边距浮起制造「卡片感」。
  • 每个业务卡都带「钩子数字」。回收「最高 ¥3200」、购买「¥1299 起」——用价格锚点替代抽象描述。
  • 故障入口从横滑 chips 改宫格。横滑会把「其他故障」藏在屏外，宫格 5 个一屏看全，点击目标也更大。
  • 质检前置。「官方质检」同时出现在搜索副标题、购买卡副文案、商品卡绿色标、底部保障四宫格—— 这是二手交易最需要反复强化的信任点。
  • 保障区下沉合并。原来「工程师上门/180天质保/先报价后修」占一行且在顶部，现在合并到页面底部与「官方质检」并列， 把首屏黄金位置让给业务入口。

四、跳转与数据来源

模块点击去向数据来源
维修主卡 / 快捷故障维修 tab静态（故障项为前端常量）
旧机回收卡回收 tab（估价）静态钩子价
严选二手机卡 / 商品卡购买 tab → 商品详情GET /api/wx/goods（已有）
热门机型卡回收 tab + 品牌预选fetchHome() 的 hotModels（已有）
搜索框v1 先跳购买 tab；v2 做聚合搜索页—

五、与旧版差异一览

  • 新增：定位 + 搜索框、购买业务卡、严选二手机横滑、官方质检标签体系。
  • 调整：热门维修 chips 横滑 → 5 宫格；三保障行 → 底部四宫格保障。
  • 保留：维修主卡（视觉强化）、回收次卡（降为半宽）、热门机型横滑与品牌预选链路。
  • 移除：无（不删任何现有入口）。

六、需要你拍板的三点

  • 购买 tab 的位置：目前是「首页 / 购买 / 维修 / 回收 / 我的」，购买排在维修之前。 如果维修仍是主推，是否考虑改成「首页 / 维修 / 购买 / 回收 / 我的」？
  • 搜索框 v1 行为：先跳购买 tab（成本低），还是直接做一个聚合搜索页（机型/故障/商品三合一）？
  • 钩子数字：卡上的「最高 ¥3200」「¥1299 起」需要真实数据支撑， 可否用接口实时取（回收取最高估价、购买取最低在售价），还是先写运营配置值？
